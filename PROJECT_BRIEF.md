# Competitor — PROJECT_BRIEF.md (single source of truth, read at the start of every task)

## Product
Maths tutor for Putnam/ICMC students that never gives the solution first. It compares HOW the expert reads a problem versus HOW the student reads it, cue by cue, through one shared schema anchored to phrases of the problem text. Protocol name: ProofReader. Not a chatbot: the dashboard is a workflow document, never a message box. Never a verdict on who did better.

## Pipeline (real calls, pending)
Call A: expert pass 1 (high effort). Call C: student extraction from photos (medium) — faithful, not charitable; every cue carries the student's own words. Call B: expert second reading, given A. `lib/compare.ts` computes the comparison (no model call). Render progressively (expert heatmap, then student, then comparison); never one long spinner. Solution reveal (the old call D plan) is dropped: the product never shows a solution. Stretch: call E ablation, one deciding cue removed at a time.
Honest framing the UI keeps: "how spotted" is a plausible expert narrative, not the model's cognition; ablation is the measured counterpart.

## Schema (shared by expert and student chains)
problem{text} — the statement exactly as typed: prose with $…$/$$…$$ maths, the single source string (write \% for a literal percent; avoid stray unpaired $). spans[{id,text,category,weight 0-100,reason}], reading{cues[{id,span_id,why_it_matters,how_spotted}],definitions[{term,meaning_latex}]}, goal{asked,answer_form,final_line_would_say}, informal_cues[{span_id,bearing}], abstraction{underneath[{object,really_is,implies}],deeper_properties[]}, simplification{instance,instance_latex,what_to_try,notice_prompt}, method{candidates[{name,deciding_span_ids,from_first_principles,kept,why}],chosen}, prerequisites[{name,needed_for,flag assumed|needed}], second_reading{new_spans,reweighted[{span_id,old,new,why}],what_changed}, domain "maths"|"not_maths".
Rules: every span is an exact substring of problem.text, checked in code — spans quote the source verbatim, so inside a formula a span is raw LaTeX (e.g. 3^0\binom{2020}{0} - …); the dashboard renders the statement as KaTeX with highlights sliced at span boundaries (a span that cuts a formula where the piece is not renderable standalone highlights the whole formula); every prose field renders $…$ inline maths; zod validates every model response; comparison is TypeScript set difference (currently hard-coded in dummy data — `lib/compare.ts` pending). Missed cues carry `span_id` + `what_it_unlocks` + `self_check`; student spans may be flagged `uncertain`. `/api/analyse` serves through the `lib/analysis.ts` provider seam (mock now, real `lib/providers/meta.ts` stubbed).

## Stack and rules
Next.js 15 App Router, TypeScript strict, Tailwind, zod, openai, katex. API routes only, no DB, no auth. Files are split by responsibility: each component does one thing, and a file is too long when it does two things, not when it passes a line count. Boring readable code; validate at the boundary; explicit loading/error states; no fetch-on-mount for user work. After every change: build, lint, verify, report.
